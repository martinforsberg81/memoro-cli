# Proposals

What you found that is not your job is a proposal: one file per finding,
`<date>-<system>-<slug>.md`, in the programme that owns the question:
`~/mc/programs/<programme>/proposals/`. That programme's interactive plan
session takes a stand on it, with the whole programme as context. When no programme owns it,
it goes in `~/mc/proposals/`, the proposals without an owner. The date, the
system and the `.md` are mc's: it counts what is there by system and orders by
name.

- The owner is the programme whose aim the change would serve: its
  `~/mc/programs/<programme>/README.md` says the aim. Pick one; the root is a
  real answer when none fits, not a failure.
- `<system>` is `mc` (memoro-cli, mc itself on this machine) or `memoro` (the
  deployed service): the one whose change would resolve it, the first when
  both would change.
- Inside it: prose, not a form — what you saw, which system and why, what you
  read, and what you would do.
- Say so in one line, with where it went, and carry on with your own work.
  Nothing wakes for it: it waits until Martin opens that programme's plan
  session.
- Not `~/mc/intake/`: that is raw material, drained one file per turn by a
  session that judges it; writing there asks a second session to work it out
  again from less than you had.
- Never touch a proposal already waiting unless your task is to consume it.
  The same rule holds for every writer: build, review, plan, helper and brief.
